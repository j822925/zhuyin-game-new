# Cloud reading with native Safari fallback

Normal fourth-level navigation stays in the existing installed Home Screen app. MediaRecorder chooses supported MP4/WebM, records at most eight seconds, and releases tracks on stop, error, hide or leave. OfflineAudioContext decodes locally; conservative energy gating, mono 16 kHz PCM WAV, and a 35-second bounded request replace the unreliable standalone SpeechRecognition path. Device selection is retained by the existing preference layer. Native speech remains available only through explicit `speech=native` fallback; its existing Safari stop/result behavior is retained.

The independent `zhuyin-reading` Worker uses the existing class-specific student sessions, not a public unauthenticated inference proxy. The main `zhuyin-api` Worker and existing gameplay backend are not replaced. `reading-service/schema.sql` only adds a global `reading_cloud_usage` counter table; no scores or student records are changed. The AI binding calls `@cf/openai/whisper-large-v3-turbo`, Chinese transcription, with no expected answer, word list, prefix or prompt. Neither audio nor transcript is saved by this application. A notice explains transmission to Cloudflare before recording. Record payloads retain the existing firstCorrect/wordId/target fields and award rules.

Server validates exact bounded PCM WAV format, duration and energy after authenticating an active class-specific session. No model call occurs for silence or bad auth. Atomic D1 reservations enforce 10 requests/minute/student, 150/day/student, 1,000/day globally and 6,000 audio seconds/day globally. Reservations are not refunded for failures. These are conservative application limits, not a reading of the account's remaining neuron balance. The account was independently verified on Workers Free; no paid upgrade or paid fallback is enabled.

`/status` closes cloud recording when a global counter is exhausted, or after Cloudflare reports error 3036 (daily free allocation exhausted). Ordinary service capacity errors do not permanently close the day. Counters reset at UTC midnight, Taiwan 08:00. Home entry checks status when mounted, every minute while visible and on return. When cloud is unavailable, it offers the original browser recognition; iPad standalone gets the existing Safari handoff with only public class/mode state. The fallback explains that an unfinished round must restart and Safari may require login. No incomplete round is scored or silently carried across browser storage boundaries. Subsequent entry after reset prefers cloud again.

Validation:
- 48 targeted tests: WAV format, server and local silence gates, revoked/cross-class auth, simultaneous quota reservations, daily reset, AI 3036 vs capacity failure, per-student/global isolation, five captures, microphone release, late-result cancellation, existing native Safari, lessons, sessions and mic checks.
- Local desktop browser fixture with simulated iPad standalone flags, microphone and server responses: silent first recording stayed on question one and made zero uploads; retry and five questions completed with three stars; all tracks released; saved score payload contained no audio. Separate exhausted fixture disabled cloud and displayed Safari fallback; explicit native mode remained usable with exhausted cloud. These are UI/integration simulations, not physical iPad verification.
- Earlier actual Cloudflare inference on five fixed synthetic Mandarin clips: 5/5 vs old tiny/base 3/5; raw silence hallucinated unrelated text, hence mandatory energy gates. Synthetic sample results do not establish child speech/tones accuracy.
- Live Worker health and availability return successfully. Reading real student/test-seat lists was rejected by automatic approval review; no private student data was read and no real student login/score was used for verification.
